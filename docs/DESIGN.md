# The Village Lawyer

Approved direction: an art-forward, browser-local village lawyer inspired by Pieter II Brueghel's 1621 painting. The user explicitly authorized replacing the older Legal Dreaming/classifier application in zgbrenner/legalflyapp.

## Product
A chamber with a villager queue, editable fact sheet, full-connectome consultation, stamped counsel, human correction, and a local case ledger. A schoolroom teaches the small artificial readout and evaluates it on different fact combinations. An activity panel shows computed activity and the exact dataset identity. The lawyer advises; it is not a judge. Customs and characters are fictional, not reconstructed historical law or present-day legal advice.

## Architecture
Dependency-free ES modules and a dedicated module worker. A local static Node server receives no submitted case text. Data preparation uses Python and NumPy, downloads checksum-pinned MaleCNS v1.0 compiled arrays, and exports an unquantized, chunked CSR graph. All 166,700 annotated neurons and 25,582,938 retained directed connections participate in every recurrent step. The previous 3,072-neuron subset is not retained as a fallback. Provenance documentation distinguishes a third-party compiled artifact from the official raw source.

Structured fields, not prose or answer labels, stimulate deterministically selected, annotated sensory neurons. Signed mathematical rate dynamics operate over the entire graph. A small supervised readout learns from neural activity, excluding directly stimulated neurons. Biological connections remain frozen. No claim of consciousness, biological learning, real legal reasoning, or superior performance.

## Interaction and storage
Load with explicit download size and cancellable progress. Train, cancel without committing a partial model, consult, correct counsel, export/import a fingerprint-bound model, export the ledger, benchmark. No automatic case persistence, analytics, external inference APIs, or fabricated activity. Missing data leaves the chamber browsable but disables inference. Reduced-motion, keyboard focus, live status announcements, and mobile layout are required.

## Art direction
A quiet, editorial chamber: warm paper, deep ink, brick-red seals, fine rules, large serif headings, original painting as the central scene. No glassmorphism, neon neural-network wallpaper, pill-heavy dashboard, or invented performance statistics. Real controls remain HTML. The activity plot is an index atlas, explicitly not an anatomical reconstruction; the illustrated fly is theatrical, not a live motor decode.

The image-generation tool failed to generate a concept. The implementation instead uses the actual public-domain painting and this written design specification. No claim of pixel fidelity to an unavailable generated concept is appropriate.

## Verification
Small fixtures test mechanics only. A separate full-data test must actually load the pinned complete graph, run training and inference, test cancellation and import rejection, compare held-out results with input-only and disconnected controls, and record timing and graph hashes. Browser tests cover the real worker as well as missing-data and responsive states. Do not describe fixture tests as biological validation or an unrun workflow as passing.
